01

Pass credentials through the right channel

The external stdio process receives a classroom API key through env. HTTP MCP servers receive an Authorization header. Keys remain on the backend and are redacted from the configuration viewer.

02

Expand project placeholders at runtime

The project experiment writes ${DEMO_MCP_TOKEN} into .mcp.json, then supplies that variable through the runtime environment. Both stdio env and HTTP headers authenticate without putting the generated credential in the file.

03

Keep OAuth in your application

The classroom provider performs a real local authorization-code flow with consent, state validation and S256 PKCE. The app exchanges the code and hands the token to the SDK. This is a local teaching provider, not GitHub OAuth or a production identity service.

04

Use GitHub with read-only scope

The GitHub example uses your locally configured PAT to connect to the real remote MCP server. It exposes only list_issues, restricts the query to three public issues and records actual connected status and completion.

05

Detect unavailable servers

Keep initialization separate from current status. Treat failed and needs-auth as unavailable; pending alone is not failure. The bad-token experiment keeps a valid server usable while the invalid-credential server supplies no data.

06

Reconnect after fixing the cause

The recovery experiment starts with a controlled HTTP outage, records the unavailable state, restores the service and invokes reconnectMcpServer on the same running query. It then requests real data on a second turn.
