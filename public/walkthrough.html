01

Logical UML participants

The diagram groups setup and alternative experiments. The local classroom OAuth provider and protected MCP service share a teaching process but represent separate logical roles. GitHub is a separate real remote service.

02

Local OAuth scope

The local provider demonstrates browser consent, one-use authorization codes, state validation and S256 PKCE. It is not GitHub OAuth, a production identity provider, a dynamic-registration implementation or a third-party refresh-token flow. The access token remains on the backend.

03

Real GitHub integration

The GitHub mode uses a personal access token from your local .env and the actual remote MCP endpoint. The server is restricted to read-only list_issues; the host fixes anthropics/claude-code, three issues and selected public fields. No comments, messages or writes are performed.

04

Connection status and errors

MCP failure can coexist with a successful model turn and another healthy server. Initialization may show pending; inspect current status before classifying a server. Query startup, model authentication or process failure can still throw, so the host retains try/catch.

05

Recovery demonstrated honestly

The recovery run fixes an intentional 503 outage and calls reconnectMcpServer on the same streaming Query. It does not claim to reproduce five automatic retries, recover an arbitrary network failure or refresh an external provider token.

06

Credentials and recordings

Classroom credentials are generated per run. Actual GitHub and model tokens come from .env. The UI and recordings show redacted config, credential-channel names and boolean/status evidence. Observation downloads omit the classroom authorization URL.

07

Token setup

Create a fine-grained GitHub PAT with public-repository read access and an expiration. Store it as GITHUB_MCP_TOKEN in .env and restart after saving. For this public issue-list exercise, private-repository and write permissions are unnecessary.
